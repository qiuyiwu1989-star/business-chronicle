# 004: 理论线结构统一（补对照与后续命运）

## 问题

读者在站里有一个断裂体验：

- 点开**企业/模式/组织/中国**节点 → 看到「当时的局面 / 关键抉择 / **同时代的对照** / 后续命运 / 今日回声」
- 点开**理论**节点 → 看到「它回答的问题 / 核心机制 / 今天怎么用 / 常见误区 / 失效条件 / 反例 / 案例 / 应用」

两套语言，读者要在脑子里切换。更要命的是：**理论线没有「对照」**。

而"每个赢家旁边放一个真实的输家"是这个站的灵魂（见 `specs/001`）。理论同样有对照——波特的定位 vs 明茨伯格的涌现、BPR 的激进 vs 持续改善、规划学派 vs 学习学派。这些对抗目前只体现在关系图谱的虚线上，**没有进入节点内容**。

## 要什么

给 `THEORY_DETAILS` 的每一条补两个字段（该数组按索引与 `THEORIES` 对应，加字段不影响索引）：

```js
{
  case, use, rel, frame,   // 既有
  rival,  // ★ 同时代的对照：谁提出了相反主张、争论的焦点是什么、后来怎么收场
  fate    // ★ 后续命运：这个理论后来如何被修正、被误用、被超越或反噬
}
```

渲染：在理论弹层的「现实应用」之后新增一个区块「同时代的对照 / 后续命运」，与三条现场线的「对照与回声」形成同构。复用 `.limit-grid` 与 `.guide-card` 样式，零新增 CSS。

## 不做什么

- **不动既有五个字段**（case/use/rel/frame 与 GUIDES/LIMITS 全部保留）。这是加法不是重写。
- 不把理论线改成 `deep` 五元组——理论与现场的差异是真实的，强行统一字段名反而失真。要统一的是**读者感受到的结构**，不是数据结构。
- 不新增 CSS 类。

## 内容红线（在 CONTEXT.md 七条之上）

1. **rival 必须是真实的学术对照**。真实存在的论战、真实的批评者、真实的竞争性理论。写不出真实对照者时，写"同时代主流做法"的真实描述，**不编造学者名字或虚构论战**。
2. **fate 要有转折**，不能写成"从此成为经典"。真实的理论命运通常是：被简化成口号、被误用、被后来者修正、或在特定条件下失效。这一栏的价值就在于打破"理论 = 真理"的错觉。
3. **不杜撰引语**。学者的话一律转述。
4. **不确定的年份与数据一律定性表述**。
5. **智能学派 5 条格外保守**——这些框架仍在形成中，fate 只能写"尚无定论"级别的观察，不预判胜负。
